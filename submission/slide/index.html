A01

Broken Access Control

Kiểm soát quyền truy cập không chặt, user có thể truy cập dữ liệu hoặc chức năng ngoài quyền.

A02

Security Misconfiguration

Cấu hình server, framework, CORS, header hoặc môi trường triển khai không an toàn.

A03

Software Supply Chain Failures

Rủi ro từ thư viện, dependency, build pipeline, artifact hoặc thành phần bên thứ ba.

A04

Cryptographic Failures

Mã hóa, truyền dữ liệu, lưu secret hoặc bảo vệ dữ liệu nhạy cảm không đúng cách.

A05

Injection

Dữ liệu đầu vào bị đưa vào SQL, command, template hoặc interpreter mà không kiểm soát đúng.

A06

Insecure Design

Thiết kế nghiệp vụ hoặc kiến trúc thiếu cơ chế phòng vệ ngay từ đầu.

A07

Authentication Failures

Xác thực, token, session, reset password hoặc quản lý tài khoản có lỗi.

A08

Software or Data Integrity Failures

Không kiểm chứng tính toàn vẹn của dữ liệu, update, CI/CD hoặc code được nạp vào hệ thống.

A09

Logging and Alerting Failures

Thiếu log, monitoring hoặc cảnh báo khiến việc phát hiện sự cố bị chậm.

A10

Mishandling of Exceptional Conditions

Xử lý lỗi hoặc ngoại lệ không an toàn, làm lộ thông tin hoặc tạo trạng thái khó kiểm soát.

SAST

Static Application Security Testing phân tích mã nguồn hoặc file cấu hình mà không cần chạy ứng dụng. Cách này phù hợp để phát hiện sớm hardcoded secret, API không an toàn, code injection, lỗi framework phổ biến và cấu hình rủi ro.

Semgrep

Semgrep là công cụ SAST chạy bằng CLI, dùng rule dạng pattern để tìm đoạn code có dấu hiệu nguy hiểm. Với đề T09, flow chính dùng ruleset p/owasp-top-ten, sau đó đưa output JSON vào script AI triage để sinh báo cáo kiểm chứng.

A07 Authentication Failures

TC-SEMGREP-001

Finding liên quan: SEMGREP-001

Mục tiêu test: Kiểm chứng khả năng giả mạo JWT khi SECRET_KEY bị hardcode trong source code.

Input

Source evidence: const SECRET_KEY = "super_secret_key_that_should_not_be_here";, jwt.sign(..., SECRET_KEY), jwt.verify(..., SECRET_KEY).

PoC: src/semgrep/exploit.js

01

Chạy PoC để tạo forged token.

node src/semgrep/exploit.js
02

Copy token sinh ra từ PoC.

03

Gửi request kiểm tra.

curl -i http://localhost:3000/api/users/me \ -H "Authorization: Bearer <forged_token>"
04

Ghi nhận status code, response body và quyền mà backend suy ra từ token.

Nếu còn lỗi

Backend chấp nhận forged token, cho phép truy cập như user/admin hợp lệ.

Nếu đã an toàn

Forged token bị từ chối, backend trả 401/403 hoặc lỗi verify JWT.

Trạng thái: Chưa kiểm chứngsubmission/User_Guide.md, mục 10.1
AI Triage Extract
15 / 33

AI triage chỉ ra root cause và đường khai thác bằng forged JWT.

01Giải thích lỗ hổng

Khóa bí mật SECRET_KEY dùng để ký và xác thực JWT được khai báo tĩnh trực tiếp trong mã nguồn tại backend/server.js.

02Proof of Concept

Khi có chuỗi super_secret_key_that_should_not_be_here, attacker có thể tự tạo JWT hợp lệ.

const jwt = require('jsonwebtoken'); const LEAKED_SECRET = "super_secret_key_that_should_not_be_here"; const payload = { id: 1, role: "admin" }; const forgedToken = jwt.sign(payload, LEAKED_SECRET); console.log("Bearer " + forgedToken);

03Mức độ ảnh hưởng

Authentication Bypass, Privilege Escalation, truy cập, sửa đổi hoặc xóa dữ liệu trái phép nếu token giả được backend tin tưởng.

04Khuyến nghị khắc phục

Không lưu secret trong source code. Chuyển SECRET_KEY sang process.env.JWT_SECRET, không commit .env, và rotate toàn bộ token cũ sau khi thay secret.

2. Package Manager winget install --id=ZAP.ZAP -e scoop install zaproxy

⚠️ Bị Gatekeeper chặn: Mở System Preferences > Security & Privacy > chọn Open anyway.
